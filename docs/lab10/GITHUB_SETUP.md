## Первая загрузка

Установить Git либо использовать GitHub Desktop. В VS Code/PyCharm открыть корень проекта Игра. Сначала проверить `git status`, существующие коммиты и состав файлов. Локальный Git уже подготовлен; удалённый адрес origin уже настроен на https://github.com/r1169/tower-404.git. Если первый коммит уже существует, повторно создавать его не нужно.

Настроить имя и email автора из собственного профиля GitHub. Коммит делать от своего имени, не создавать коммиты от имени напарницы.

```text
git config user.name "СВОЁ ИМЯ"
git config user.email "СВОЙ EMAIL ИЗ GITHUB"
git add README.md .gitignore package.json scripts skyflow docs prototypes
git commit -m "Add Tower 404 prototype and lab 10 project plan"
git branch -M main
git remote add origin https://github.com/r1169/tower-404.git
git push -u origin main
```

Выполнять `remote add` только если адрес `origin` ещё не настроен, а репозиторий с таким именем действительно создан. Авторизация выполняется стандартным окном GitHub; токены не сохранять в README и адресе remote.

## Участники

Settings → Collaborators: пригласить преподавателя по проверенным логинам. Приглашение и принятый доступ — разные состояния. Проверить, что приглашения приняты. Преподавателю выдать минимальный доступ, доступный выбранному типу репозитория; при необходимости согласовать права. Логины других людей не угадывать.

Ляззат после получения доступа клонирует репозиторий через GitHub Desktop, VS Code или `git clone` и запускает игру по README. Для совместной работы перед изменениями получает последние изменения, создаёт отдельную ветку, делает собственный содержательный коммит и Pull Request. Рахим проверяет её изменения; свои изменения Рахим отдаёт Ляззат на просмотр.

## Issues и доска

Создать приватный GitHub Project и привязать к репозиторию. Столбцы статуса: Backlog → To Do → In Progress → Testing → Done. Добавить задачи из WBS.csv; для каждой указать WBS ID, критерий готовности, приоритет, учебную неделю и зависимость. Назначить реальных участников после получения доступа. Закрытые Done-задачи описывают уже реализованное поведение, а не вымышленную историю коммитов.

`ISSUES_IMPORT.json` содержит заготовки заголовков и тел. Он не является подтверждением создания Issues. В `PLAN_DATA.json` и локальной доске остаётся исходный снимок планирования; после создания GitHub-доски её статусы нужно поддерживать согласованно.
